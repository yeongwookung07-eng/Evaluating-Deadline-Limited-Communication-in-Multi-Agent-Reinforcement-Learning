# Attribution boundary checks

This component reanalyzes retained deadline-communication traces. It asks when the Full–RR identity follows structurally from matched delivery, whether equal traffic/return hides different behavior in the same frozen-policy cohort, how a common RR prefix changes full history, and which measured preparation times cross delivery thresholds. It does not introduce a scheduler or alter earlier experiments.

Registered 2026-11-23 before execution: `structural_history_audit.py`, `../configs/attribution_structural_history.yaml`. Inputs are the retained identity, prefix, readiness and three independent-process timing logs. The mathematical contract is deterministic transition/policy replay under equal weights, initial full state, cache rule, ordered sender payload/timestamp arrivals and identical exogenous randomness. These conditions imply equal policy/environment evolution inductively; an equal count alone does not. The single-packet rotating queue is an explicit sufficient specialization, not a universal statement.

Primary estimates average episodes within each training seed and weight ten seeds equally; timestep-weighted alternatives are separately labeled. Common-prefix intervention changes joint history and cannot uniquely identify cache initialization as mediator. Recorded sender lists are sorted, so exact receive order is inferred from the known queue rule rather than claimed observed. No new source transmission/hardware cost is measured.

### Findings and adoption

- Structural identity: fixed weights/reset/cache and sender-keyed payload/timestamp identity imply equal deterministic control evolution. Full's rotating queue and RR's cursor necessarily coincide when precisely one packet is admitted/delivered per step. With constant k<N, their starting indices differ by (k−1)t modulo N; k=1 is the guaranteed case. This explains why 400 Slow pairs validate the implementation and conditional counterexample, rather than establishing broad scheduler equivalence.
- Same cohort, three levels: Slow Full–RR saves 80% offered bytes/step and preserves all 400 information/action/return histories. Medium/2 ms Full–RR saves 60% offered bytes/step; packet counts agree on every common step, but sender histories differ in all 400 pairs (first t=1). Full episode count sequences agree in 349/400 because some durations diverge. Returns agree in 259/400, and 222 of those equal-return pairs have different action histories. Thus aggregate cost/return, observed behavior and matched-history attribution give different answers within one frozen cohort. Numbers pool two cache settings descriptively; seed-level summaries remain separate per setting.
- Joint prefix: Slow has 0/400 return changes despite126 differing sender and94 differing action traces on common suffix support. Medium has15/400 return changes. The prefix equalizes joint environment/policy/cache/scheduler history, so it does not uniquely identify cache filling as mediator.
- Slack: at2.25ms, three48-byte packets on100000B/s require readiness≤310us. Episode-first RR delivery means over three processes are2.2060,2.0048,2.0024 versus DAC2.0000 each. The original process is2.1754 versus1.9986. Step-first alternatives are retained in JSON, not silently interchanged.
- Same-input costs: episode-first DAC gate overhead is98.2,99.7,100.3us across processes, but those saved matched snapshots have zero delivered-count difference. A repeated overhead does not imply a stable packet-loss magnitude. Credit and actual admission also matter; average readiness alone cannot predict opportunity.

Adopt the conditional identity statement, same-cohort count/behavior/return distinction, history-only prefix interpretation and process-specific timing claim. Reject generic80% physical-network savings, pure initialization mediation, robust DAC superiority and native-method generalization. The analysis adds no learned benchmark, training remedy, hardware replication or new deployment timing.
