# Evaluating Deadline-Limited Communication in Multi-Agent Reinforcement Learning: Delivery, Computation, and Control

**When several agents want to send a message but only one packet can arrive before they must act, what does the team gain by choosing who sends?** In our five-agent Hallway task, sending only the first packet in the queue saves four transmissions and gives every receiver exactly the update it would have received if all five agents had transmitted. Giving that same slot to another sender costs the same number of bytes and can change the team's next action.

This study asks how to trace a difference in traffic or reward back to the decision that produced it. We first check how well the trained policy performs and whether it benefits from messages. We then record which updates arrive on time and which earlier messages remain in each receiver's memory. To measure the effect of sender identity, we hold the policy and its history fixed, replace one sender for a single decision, and follow the resulting actions and rewards to the end of the episode. Finally, we check which action the receiver actually executes when computation takes time. ## What the experiments show

**Delivery.** In Hallway, two rules each reduced offered bytes by 80%. Round-robin access preserved every received update, action and reward across 400 paired episodes. The priority rule changed the sender history in every pair. When cached messages retained their full weight, mean return fell by 1.95 points relative to offering all five packets. These policies were trained with privileged demonstrations. A controller using local distance and a shared clock can solve the task without messages.

**Sender choice.** We repeated the one-decision substitution in two sequential environments, using three independently trained policies per task. Changing the sender changed subsequent return at 27 of 30 sampled decisions in SMACv2 Terran and 22 of 139 in SchedNet Predator–Prey. At five Terran decisions, all five senders produced the same immediate joint action, yet later rewards differed. In both tasks the seed-level intervals for the original sender's average advantage over a uniformly chosen sender included zero. [Replay conditions and recorded trajectories](docs/SEQUENTIAL_SENDER_REPLAY.md)

**Computation and receiver behavior.** In the MNIST-sum digit game, admitting a packet when it was expected to be ready improved accuracy at equal offered traffic. The gain reversed when readiness estimates were sufficiently noisy and costly to compute. In a separate broadcast task with a 2 ms deadline, fitting the receiver on labeled examples improved executed accuracy by 5.63 percentage points when overruns were rare. With 500 microseconds of added processing, every candidate missed the deadline and each receiver repeated its previous action. ## Results

A sender comparison in this study changes one decision and then resumes the original scheduling rule. The reported uncertainty is calculated across independently trained policies. The many replayed branches within a policy share its weights and initial conditions. The packet deadlines and measured computation costs apply to the tested settings. Predator–Prey uses its native sender slot and has no transport deadline.
